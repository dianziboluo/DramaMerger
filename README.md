# 短剧合并工具 (Drama Merger)

[中文](README.md) | [English](README_EN.md)

一个 **Windows 桌面工具**，把分散在文件夹里的短剧 / 分集视频**无损合并**成一个完整视频文件，并支持**增量更新**：日后下载了新集数，再跑一次即可自动追加到已合并文件的末尾，文件名也会自动更新（如 `第1-10集` → `第1-12集`）。

基于 .NET 8 (WinForms) + ffmpeg 无损拼接（`-c copy`，不转码），合并 1GB 素材通常只需几秒。

## ✨ 功能

- 📺 **自动识别剧集**：从文件名中的 `第01集` / `EP01` 等模式解析集数，按集数数字排序（不会出现第10集排在第2集前面的问题）
- 🔗 **无损合并**：调用 ffmpeg `-c copy` 直接拼接，不重新编码，画质无损、速度快
- 🈶 **中英双语界面**：右上角一键切换，自动记住选择
- 📈 **增量更新**：输出目录中的隐藏清单文件记录已合并集数；新集数下载好后再次运行，自动追加并重命名（`第1-10集` → `第1-12集`），旧文件自动清理
- 📁 **多文件夹载入**：旧剧集文件夹和新下载文件夹分开存放？全部添加进来勾选即可，程序会跨文件夹合并扫描
- 🗂️ **批量模式**：一个根目录下每部剧一个子文件夹，勾选批量模式一次性全部合并，统一输出
- 🛡️ **安全校验**：同一集数出现多个文件、集数不连续、源文件被改动等都会明确提示，同名输出不会静默覆盖数据
- 📊 **真实进度**：通过 ffprobe 读取总时长，显示整体合并进度条，可随时取消

## 📦 下载使用

### 环境要求

- Windows 10 / 11 (x64)
- [ffmpeg](https://www.gyan.dev/ffmpeg/builds/)（需要 `ffmpeg.exe` 和 `ffprobe.exe` 在 PATH 中，或放在本程序同目录下）

### 使用步骤

1. 运行 `短剧合并工具.exe`（单文件，无需安装）
2. 点「添加文件夹…」加入剧集所在文件夹并勾选
3. 选择输出文件夹，点击「扫描并合并」
4. 确认计划 → 等待完成

### 增量更新（追加剧集）

已合并第 1-10 集后，下载了第 11、12 集：

1. 把新集数放进已勾选的任意剧集文件夹（或添加新文件夹）
2. 再点一次「扫描并合并」
3. 程序识别出新集数，追加到现有文件末尾，输出自动变成 `剧名 第1-12集.mp4`，旧的 `第1-10集` 文件被清理

### 批量模式

```
D:\短剧\
├─ 剧A\        ← 第01集 ~ 第10集.mp4
├─ 剧B\        ← 第01集 ~ 第08集.mp4
└─ 剧C\
```

勾选「批量模式（每个子文件夹 = 一部剧）」，选择根目录，一次性合并所有剧到统一输出目录。清单按剧名分开记录，日后某部剧更新，重跑批量只处理有新集数的那部。

## 🔢 集数识别规则

| 文件名示例 | 识别集数 |
|---|---|
| `被潜规则的女孩 第07集.mp4` | 7 |
| `Some Drama EP05.mp4` | 5 |
| `Show Episode 12.mp4` | 12 |
| `特别篇 SP.mp4`（无编号） | 不参与合并 |
| `被潜规则的女孩 第1-10集.mp4`（合并产物） | 不参与（避免自我重复） |

输出命名：中文界面 `剧名 第1-10集.mp4`，英文界面 `DramaName EP1-10.mp4`。

合并产物放回剧集文件夹也不会被误识别——`第1-10集` 不匹配单集编号格式。

## 🛠️ 从源码构建

```powershell
git clone https://github.com/dianziboluo/DramaMerger.git
cd DramaMerger
dotnet build -c Release
dotnet publish -c Release   # 单文件 exe 输出在 bin\Release\net8.0-windows\win-x64\publish\
```

需要 .NET 8 SDK（[下载地址](https://dotnet.microsoft.com/download/dotnet/8.0)）。

## ⚙️ 工作原理

1. **扫描**：`Directory.EnumerateFiles` + 正则解析集数，按数字排序，跨勾选文件夹去重
2. **计划**：读取输出目录中的合并清单（`.merge-manifest-剧名.json`），对比当前文件，决定「全新合并 / 增量追加 / 已是最新 / 缺集 / 源变动」
3. **合并**：生成 ffmpeg concat 列表 → `ffmpeg -f concat -safe 0 -c copy -movflags +faststart` → 先写临时文件，成功后原子替换
4. **更新清单**：记录已合并的文件名与大小，供下次增量判断

> 无损拼接要求各集编码参数一致（同一部剧通常满足）。若 ffmpeg 报错，日志中会给出完整错误信息。

## ❓ FAQ

**Q: 会转码 / 损耗画质吗？**
不会。使用 `-c copy` 直接拼接封装层，视频流原样复制。

**Q: 清单文件是什么？能删吗？**
输出目录中的 `.merge-manifest-剧名.json`，记录已合并的集数信息。删掉后程序会走"全新合并"，不会丢数据，但会重新生成完整文件。

**Q: 提示「缺第 X 集」？**
集数必须连续才能保证观看顺序。把缺失的集数文件放进文件夹后重试。

**Q: 提示「第 X 集有多个视频文件」？**
同一集数有两个文件（比如重复下载），删掉一个再试。
